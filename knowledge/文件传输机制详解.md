## 一、消息发送到 Socket 的完整流程

### 1.1 入口：Channel.write() / writeAndFlush()

```java
// Channel.java:271-273
default ChannelFuture write(Object msg) {
    return pipeline().write(msg);
}
```

`Channel` 的 write 方法直接委托给 `ChannelPipeline`。

### 1.2 Pipeline 传播：DefaultChannelPipeline

消息从 `TailContext` 开始，逆向传播到 `HeadContext`，经过所有用户添加的 `ChannelOutboundHandler`。

### 1.3 核心写入：AbstractChannel.AbstractUnsafe.write()

位置：`transport/src/main/java/io/netty/channel/AbstractChannel.java:718-754`

```java
public final void write(Object msg, ChannelPromise promise) {
    assertEventLoop();  // 确保在 EventLoop 线程中执行

    ChannelOutboundBuffer outboundBuffer = this.outboundBuffer;
    if (outboundBuffer == null) {
        try {
            // release message now to prevent resource-leak
            ReferenceCountUtil.release(msg);
        } finally {
            safeSetFailure(promise,
                    newClosedChannelException(initialCloseCause, "write(Object, ChannelPromise)"));
        }
        return;
    }

    int size;
    try {
        // 1. 过滤消息（子类可重写）
        msg = filterOutboundMessage(msg);

        // 2. 估算消息大小
        size = pipeline.estimatorHandle().size(msg);
        if (size < 0) {
            size = 0;
        }
    } catch (Throwable t) {
        try {
            ReferenceCountUtil.release(msg);
        } finally {
            safeSetFailure(promise, t);
        }
        return;
    }

    // 3. 添加到出站缓冲区（此时消息并未真正发送）
    outboundBuffer.addMessage(msg, size, promise);
}
```

**注意**：此时消息并没有真正写入 socket，只是被放到了 `ChannelOutboundBuffer` 中。

### 1.4 刷新操作：flush()

位置：`AbstractChannel.java:757-767`

```java
public final void flush() {
    assertEventLoop();

    ChannelOutboundBuffer outboundBuffer = this.outboundBuffer;
    if (outboundBuffer == null) {
        return;
    }

    // 1. 标记刷新操作
    outboundBuffer.addFlush();

    // 2. 执行实际的写入
    flush0();
}
```

### 1.5 实际写入：flush0() → doWrite()

位置：`AbstractChannel.java:770-808`

```java
protected void flush0() {
    // 防止重入
    if (inFlush0) return;

    inFlush0 = true;
    try {
        // 调用子类实现的 doWrite
        doWrite(outboundBuffer);
    } finally {
        inFlush0 = false;
    }
}
```

### 1.6 NIO Socket 写入：NioSocketChannel.doWrite()

位置：`transport/src/main/java/io/netty/channel/socket/nio/NioSocketChannel.java:379-439`

这是最关键的部分，真正将数据写入底层 socket：

```java
@Override
protected void doWrite(ChannelOutboundBuffer in) throws Exception {
    SocketChannel ch = javaChannel();  // 获取 Java NIO SocketChannel
    int writeSpinCount = config().getWriteSpinCount();

    do {
        if (in.isEmpty()) {
            // All written so clear OP_WRITE
            clearOpWrite();
            return;
        }

        // 1. 从缓冲区获取 NIO ByteBuffer 数组
        int maxBytesPerGatheringWrite = ((NioSocketChannelConfig) config).getMaxBytesPerGatheringWrite();
        ByteBuffer[] nioBuffers = in.nioBuffers(1024, maxBytesPerGatheringWrite);
        int nioBufferCnt = in.nioBufferCount();

        // 2. 根据 buffer 数量选择写入方式
        switch (nioBufferCnt) {
            case 0:
                // 非 ByteBuf 类型
                writeSpinCount -= doWrite0(in);
                break;
            case 1: {
                // 单个 ByteBuf - 非聚合写入
                ByteBuffer buffer = nioBuffers[0];
                int attemptedBytes = buffer.remaining();
                final int localWrittenBytes = ch.write(buffer);  // ⭐ 调用 NIO 写入
                if (localWrittenBytes <= 0) {
                    incompleteWrite(true);
                    return;
                }
                adjustMaxBytesPerGatheringWrite(attemptedBytes, localWrittenBytes, maxBytesPerGatheringWrite);
                in.removeBytes(localWrittenBytes);
                --writeSpinCount;
                break;
            }
            default: {
                // 多个 ByteBuf - 聚合写入（Gathering Write）
                long attemptedBytes = in.nioBufferSize();
                final long localWrittenBytes = ch.write(nioBuffers, 0, nioBufferCnt);  // ⭐ 聚合写入
                if (localWrittenBytes <= 0) {
                    incompleteWrite(true);
                    return;
                }
                adjustMaxBytesPerGatheringWrite((int) attemptedBytes, (int) localWrittenBytes,
                        maxBytesPerGatheringWrite);
                in.removeBytes(localWrittenBytes);
                --writeSpinCount;
                break;
            }
        }
    } while (writeSpinCount > 0);

    incompleteWrite(writeSpinCount < 0);
}
```

**关键点**：
- `ch.write(buffer)` - 直接调用 Java NIO 的 `SocketChannel.write()` 方法
- 支持单 buffer 写入和 gathering write（多 buffer 一次性写入）

## 二、明文文件传输（零拷贝）

### 2.1 FileRegion 接口

位置：`transport/src/main/java/io/netty/channel/FileRegion.java`

```java
public interface FileRegion extends ReferenceCounted {
    long position();           // 文件起始位置
    long transferred();        // 已传输的字节数
    long count();              // 要传输的总字节数

    // 核心方法：传输数据到目标 Channel
    long transferTo(WritableByteChannel target, long position) throws IOException;
}
```

### 2.2 DefaultFileRegion 实现

位置：`transport/src/main/java/io/netty/channel/DefaultFileRegion.java`

**核心特性：**
- 支持从 `FileChannel` 或 `File` 创建文件区域
- 使用 `FileChannel.transferTo()` 实现零拷贝
- 实现引用计数，确保资源正确释放
- 自动关闭底层 FileChannel

**transferTo 方法实现：**

```java
@Override
public long transferTo(WritableByteChannel target, long position) throws IOException {
    long count = this.count - position;

    // 核心零拷贝操作
    long written = file.transferTo(this.position + position, count, target);
    if (written > 0) {
        transferred += written;
    }
    return written;
}
```

### 2.3 NIO Socket 文件传输实现

位置：`transport/src/main/java/io/netty/channel/socket/nio/NioSocketChannel.java:360-363`

```java
@Override
protected long doWriteFileRegion(FileRegion region) throws Exception {
    final long position = region.transferred();
    return region.transferTo(javaChannel(), position);
}
```

### 2.4 零拷贝原理图

```
普通 ByteBuf 写入：
┌─────────┐    拷贝    ┌─────────┐    拷贝    ┌─────────┐    拷贝    ┌─────────┐
│  文件   │  ──────>  │ JVM堆   │  ──────>  │ 用户态  │  ──────>  │ 网卡    │
└─────────┘           └─────────┘           └─────────┘           └─────────┘

FileRegion 零拷贝：
┌─────────┐    直接    ┌─────────┐
│  文件   │  ──────>  │ 网卡    │

└─────────┘           └─────────┘
```

### 2.5 使用示例

```java
// 传统方式 - 需要将文件加载到内存
byte[] fileBytes = Files.readAllBytes(path);
channel.write(Unpooled.wrappedBuffer(fileBytes));

// 零拷贝方式 - 直接从文件传输
FileChannel fileChannel = FileChannel.open(path, StandardOpenOption.READ);
FileRegion region = new DefaultFileRegion(fileChannel, 0, fileChannel.size());
channel.writeAndFlush(region).addListener(future -> {
    fileChannel.close();  // 传输完成后关闭
});
```

## 三、加密文件传输

### 3.1 为什么 FileRegion 不能用于加密？

`FileRegion` 使用 `FileChannel.transferTo()` 实现零拷贝，数据直接从文件系统内核缓冲区传输到网络协议栈。但加密（如 SSL/TLS）需要：

1. 读取明文数据到用户空间
2. 进行加密处理
3. 发送密文数据

因此**零拷贝和加密互斥** - 加密必须在用户空间处理数据。

### 3.2 核心组件

#### 3.2.1 ChunkedFile - 分块文件读取器

位置：`handler/src/main/java/io/netty/handler/stream/ChunkedFile.java`

```java
public class ChunkedFile implements ChunkedInput<ByteBuf> {
    private final RandomAccessFile file;
    private final long startOffset;
    private final long endOffset;
    private final int chunkSize;  // 每块大小，默认 8192
    private long offset;

    // 每次读取一块数据
    @Override
    public ByteBuf readChunk(ChannelHandlerContext ctx) throws Exception {
        // ...
    }
}
```

#### 3.2.2 ChunkedWriteHandler - 分块写入处理器

位置：`handler/src/main/java/io/netty/handler/stream/ChunkedWriteHandler.java`

```java
public class ChunkedWriteHandler extends ChannelDuplexHandler {
    // 持续从 ChunkedInput 读取数据块
    // 将每个块转换为 ByteBuf 发送
    // 支持异步非阻塞写入
}
```

**功能：**
- 持续从 `ChunkedInput` 读取数据块
- 将每个块转换为 `ByteBuf` 发送
- 支持异步非阻塞写入
- 自动处理背压（当 socket 写缓冲区满时暂停发送）

### 3.3 官方示例：HTTP 文件服务器的处理

位置：`example/src/main/java/io/netty/example/http/file/HttpStaticFileServerHandler.java:198-209`

```java
ChannelFuture sendFileFuture;
ChannelFuture lastContentFuture;

// 关键判断：根据是否使用 SSL 选择传输方式
if (ctx.pipeline().get(SslHandler.class) == null) {
    // 非加密：使用 FileRegion 零拷贝
    sendFileFuture = ctx.write(
        new DefaultFileRegion(raf.getChannel(), 0, fileLength),
        ctx.newProgressivePromise()
    );
    // Write the end marker.
    lastContentFuture = ctx.writeAndFlush(LastHttpContent.EMPTY_LAST_CONTENT);
} else {
    // 加密：使用 ChunkedFile 分块传输
    sendFileFuture = ctx.writeAndFlush(
        new HttpChunkedInput(new ChunkedFile(raf, 0, fileLength, 8192)),
        ctx.newProgressivePromise()
    );
    // HttpChunkedInput will write the end marker (LastHttpContent) for us.
    lastContentFuture = sendFileFuture;
}
```

### 3.4 Pipeline 配置

位置：`example/src/main/java/io/netty/example/http/file/HttpStaticFileServerInitializer.java:35-44`

```java
@Override
public void initChannel(SocketChannel ch) {
    ChannelPipeline pipeline = ch.pipeline();

    // 1. SSL 处理器（如果启用）
    if (sslCtx != null) {
        pipeline.addLast(sslCtx.newHandler(ch.alloc()));
    }

    // 2. HTTP 编解码器
    pipeline.addLast(new HttpServerCodec());
    pipeline.addLast(new HttpObjectAggregator(65536));

    // 3. 分块写入处理器（支持大文件和加密传输）
    pipeline.addLast(new ChunkedWriteHandler());

    // 4. 业务处理器
    pipeline.addLast(new HttpStaticFileServerHandler());
}
```

### 3.5 完整数据流

```
┌─────────────────────────────────────────────────────────────────────┐
│                         加密文件传输流程                              │
└─────────────────────────────────────────────────────────────────────┘

非加密传输（零拷贝）：
┌─────────────┐    transferTo()    ┌─────────────┐
│  FileRegion │  ──────────────>   │ 网络socket  │
│ (零拷贝)     │                    │             │
└─────────────┘                    └─────────────┘

加密传输（分块处理）：
┌─────────────┐    readChunk()    ┌─────────────┐    加密    ┌─────────────┐
│ ChunkedFile │  ──────────────>  │   ByteBuf   │  ──────>  │ SslHandler  │
│ (分块读取)   │                   │ (明文数据)   │           │ (TLS加密)   │
└─────────────┘                    └─────────────┘           └──────┬──────┘
                                                                    ▼
                                                            ┌─────────────┐
                                                            │ 网络socket  │
                                                            │  (密文)     │
                                                            └─────────────┘

详细流程：
1. ChunkedFile 从文件读取一块数据（如 8KB）
2. 转换为 ByteBuf（明文）
3. 传递给 SslHandler 进行加密
4. 加密后的数据写入 socket
5. 重复直到文件结束
```

## 四、两种方式的对比

| 特性 | 非加密（FileRegion） | 加密（ChunkedFile + SslHandler） |
|------|---------------------|--------------------------------|
| **数据源** | 文件系统 | JVM 内存 |
| **拷贝次数** | 零拷贝（1-2次） | 需要拷贝（3-4次） |
| **内存使用** | 极低（不加载到堆内存） | 需要占用堆或直接内存 |
| **适用场景** | 大文件传输 | 需要加密的场景 |
| **性能** | 高吞吐量 | 较低（需要加密） |
| **传输控制** | 通过 `transferred()` 跟踪传输进度 | 通过分块数量跟踪 |
| **Pipeline 要求** | 不需要 ChunkedWriteHandler | 必须添加 ChunkedWriteHandler |
| **SSL 支持** | 不支持 | 支持 |

## 五、最佳实践

### 5.1 服务端配置示例

```java
public class SecureFileServerInitializer extends ChannelInitializer<SocketChannel> {

    private final SslContext sslCtx;

    public SecureFileServerInitializer(SslContext sslCtx) {
        this.sslCtx = sslCtx;
    }

    @Override
    public void initChannel(SocketChannel ch) {
        ChannelPipeline pipeline = ch.pipeline();

        // SSL/TLS 加密层
        pipeline.addLast("ssl", sslCtx.newHandler(ch.alloc()));

        // HTTP 编解码
        pipeline.addLast("codec", new HttpServerCodec());
        pipeline.addLast("aggregator", new HttpObjectAggregator(65536));

        // 分块写入处理器 - 必须添加，支持大文件加密传输
        pipeline.addLast("chunkedWriter", new ChunkedWriteHandler());

        // 业务处理
        pipeline.addLast("handler", new FileServerHandler());
    }
}
```

### 5.2 文件发送代码示例

```java
public class FileServerHandler extends SimpleChannelInboundHandler<FullHttpRequest> {

    @Override
    protected void channelRead0(ChannelHandlerContext ctx, FullHttpRequest request)
            throws Exception {

        String filePath = "/path/to/large/file.zip";
        RandomAccessFile raf = new RandomAccessFile(filePath, "r");
        long fileLength = raf.length();

        // 发送 HTTP 响应头
        HttpResponse response = new DefaultHttpResponse(HTTP_1_1, OK);
        HttpUtil.setContentLength(response, fileLength);
        response.headers().set(HttpHeaderNames.CONTENT_TYPE, "application/zip");
        ctx.write(response);

        // 判断是否使用 SSL
        boolean isSsl = ctx.pipeline().get(SslHandler.class) != null;

        ChannelFuture sendFileFuture;
        if (isSsl) {
            // 加密传输：使用 ChunkedFile
            sendFileFuture = ctx.writeAndFlush(
                new HttpChunkedInput(new ChunkedFile(raf, 0, fileLength, 8192))
            );
        } else {
            // 非加密传输：使用 FileRegion 零拷贝
            sendFileFuture = ctx.write(
                new DefaultFileRegion(raf.getChannel(), 0, fileLength)
            );
            ctx.writeAndFlush(LastHttpContent.EMPTY_LAST_CONTENT);
        }

        // 监听传输完成
        sendFileFuture.addListener(new ChannelProgressiveFutureListener() {
            @Override
            public void operationProgressed(ChannelProgressiveFuture future,
                                           long progress, long total) {
                if (total < 0) {
                    System.err.println("Transfer progress: " + progress);
                } else {
                    System.err.println("Transfer progress: " + progress + " / " + total);
                }
            }

            @Override
            public void operationComplete(ChannelProgressiveFuture future) {
                System.err.println("Transfer complete: " + future.isSuccess());
            }
        });
    }
}
```

### 5.3 关键要点

1. **检测 SSL** - 根据 pipeline 中是否有 `SslHandler` 选择传输方式
2. **ChunkedWriteHandler** - 加密传输时必须添加
3. **Chunk 大小** - 默认 8192 字节，可根据网络状况调整
4. **资源管理** - 使用 `HttpChunkedInput` 会自动关闭底层的 `ChunkedFile`
5. **进度监听** - 使用 `ChannelProgressiveFutureListener` 监控大文件传输进度
6. **错误处理** - 注意处理传输失败的情况

### 5.4 完整的 Pipeline 结构

```
非加密文件传输：
SocketChannel
    ↓
HttpServerCodec (HTTP 编解码)
    ↓
HttpObjectAggregator (消息聚合)
    ↓
YourHandler (业务逻辑)
    ↓
FileRegion (零拷贝传输)

加密文件传输：
SocketChannel
    ↓
SslHandler (加密层)
    ↓
HttpServerCodec (HTTP 编解码)
    ↓
HttpObjectAggregator (消息聚合)
    ↓
ChunkedWriteHandler (分块写入 - 必须)
    ↓
YourHandler (业务逻辑)
    ↓
ChunkedFile (分块读取)
```

## 总结

Netty 提供了两种文件传输方式：

1. **FileRegion（零拷贝）** - 适用于非加密场景，性能最优
2. **ChunkedFile + SslHandler（加密传输）** - 适用于需要加密的场景

在实际开发中，应根据是否需要加密来选择合适的传输方式，并正确配置 Pipeline。
